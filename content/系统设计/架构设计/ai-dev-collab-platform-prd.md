一、 市场调研与竞品分析

目前市场上尚无一款完完全全把“DevOps 流程看板 + AI 会话历史持久化 + 跨部门资产共享 + 多仓库/工具接入”打包封装成极致一体化的开箱即用开源平台，但存在单点能力极强的产品：

1. 商业/开源竞品参照

GitLab / GitHub Copilot Workspace：实现了“需求/Issue -> AI 深入代码上下文分析 -> 自动生成 PR”的闭环，但它是基于代码库维度的，缺乏对团队跨部门（如测试、PM）会话上下文的无缝协同传递与内部 Prompt 资产库管理。   
GitHub

Gentle-AI / OpenCode / SuperAGI：开源的 Agent 编排框架，能够存取历史 Session（即上下文持久化），但偏向于纯开发者工具或 CLI，缺乏可视化需求看板与项目/团队权限隔离。

ai-todo：基于 MCP 协议在代码仓库中持久化任务上下文的轻量工具，但缺少图形化交互与协作维度。

2. 结论与定位

你的设想在企业内部落地价值极高。市场上缺失的是将 “项目管理看板 (PM/QA/Dev)” 与 “AI Agent Stateful Session (记忆/上下文持久化)” 深度集成的内部研发一体化协同平台。

二、 用户痛点与核心价值（为什么做？）
角色	真实痛点	平台提休/解决方案
QA/测试	发现 UI/接口 Bug 后描述不清；提了 Bug 给前端，前端问“怎么复现的？之前你问 AI 说了什么？”	测试直接在平台发起 AI 对话调试，定位完问题后把整个 AI 会话指派给前端，无需二次转述。
前端/后端	接手别人的需求/Bug 时，上个开发留下的分析思路和调试上下文丢失，需要重新排查代码。	继承历史会话，接着上文直接向 AI 发指令：“根据上面的排查记录，直接生成 Patch 代码并提交。”
团队/公司	每个人的调优 Prompt、技术修复经验存留在个人电脑或本地终端里，离职即丢失。	对话与 Prompt 统一落库，转变为公司内部的可复用资产，并作为后续 RAG 的知识来源。
三、 MVP 极速 Demo 方案（核心场景与设计）

为了用最短的时间（建议 1.5 ~ 2 周）验证核心逻辑，MVP 必须遵循 “极简协作 + 上下文继承 + 仓库连通” 的原则，剔除不必要的复杂功能。

1. 核心流程演练（MVP 覆盖场景）
[步骤 1: 创建需求/Bug]
PM /QA 在平台新建任务: "首页列表渲染延迟" -> 绑定 GitLab 仓库 & 分支

[步骤 2: QA 发起 AI 协同排查]
QA 在任务详情页直接与 AI 对话: "提示组件加载失败"
-> AI 联动代码库/接口日志分析，给出初步诊断思路。

[步骤 3: 无缝上下文继承 (Handoff)]
QA 发现需要修改代码，把任务指派给 [前端开发 A]。
前端 A 打开页面，看得到 QA 之前的全部会话 -> 接着回复 AI: "请帮我修改此组件"

[步骤 4: 自动落库与资产生成]
修复完成后，会话作为 Session 归档，Prompt 保存至公共模版库，供全员调用。

2. MVP 功能架构与模块划分

MVP 版本仅保留 4 个核心模块：

模块 A：轻量工作台与任务关联 (Workspace & Tasks)

功能：简单看板，支持按项目分类，支持三种状态：待办、进行中、已完成。   
GitHub

关键属性：任务名称、负责人、关联 GitLab/GitHub 仓库地址、绑定的 Agent Session ID。   
GitHub

模块 B：带上下文持久化的 AI 对话 (Stateful Chat Engine)

功能：   
GitHub

会话绑定：每个 Task 绑定固定的 session_id。

历史追溯与继承：B 接入任务时，自动加载 A 之前产生的所有 Message 历史。

模型切换与流控：底部提供简易模型切换（如 Standard / High 模式）与 Token 计数。

模块 C：共享 Prompt 资产库 (Prompt Assets Hub)

功能：

预置通用规范（如“前端 Vue3 重构模板”、“接口调试 Prompt”）。

支持在对话框中通过键盘快捷键 / 唤起企业预置 Prompt 模板。

模块 D：GitLab / 飞书简易连通器 (Connectors)

功能：

代码库连通：通过 GitLab API/ Personal Access Token 读取仓库目录结构与目标文件。

飞书通知：任务指派给他人或 AI 诊断完成时，向飞书卡片推送任务链接。

1. 推荐技术栈选型

前端：Next.js 14 + Tailwind CSS + Shadcn UI + Monaco Editor（代码渲染）。

后端：Python FastAPI（生态成熟，极速对接 LangChain/LangGraph 与 Agent 框架）。

Agent 状态机：使用 LangGraph。它天生支持带 State 的多轮工作流及 Session 持久化（State Persistence）。

存储：PostgreSQL (存储业务数据、会话 JSONL 与 Prompt 资产) + Redis (存储 Chat SSE 流状态)。

五、 后续迭代 Roadmap（MVP 上线后）

V1.5 - 自动分支与代码 Patch 修改：Agent 不仅能查看代码，还能直接生成 Git Patch，点击按钮即可一键在 GitLab 创建 Merge Request。

V2.0 - 沉淀知识库 (RAG Hub)：自动将解决过的 Bug 对话及高质量 Session 进行向量化，后续出现类似 Bug 时，AI 自动推荐“历史相似问题的排查方案”。

V2.5 - 代码沙盒执行 (Docker Enterprise Sandbox)：右侧直接集成 WASM 或 Docker 运行环境，Agent 可以在隔离沙盒里自动跑单元测试验证修复结果。
