## 题目
go 的切片 按行遍历和按列遍历 在性能上有什么区别

## 回答
在 Go 语言中，切片的按行遍历（Row-Major）和按列遍历（Column-Major）在性能上通常有数量级级别的差异。按行遍历的性能远高于按列遍历，其根本原因在于 CPU 缓存局部性（Cache Locality） 和内存访问模式。

核心结论
遍历方式	内存访问模式	CPU 缓存命中率	性能表现
按行遍历	连续内存访问（Sequential）	极高（连续加载到 Cache Line）	极快
按列遍历	跳跃/跨步访问（Strided/Non-contiguous）	极低（频繁发生 Cache Miss）	显著变慢（可能慢数倍甚至数十倍）
为什么会有性能差距？（底层原理）
1. 硬件层面的 CPU 缓存（Cache）

现代 CPU 从主存（RAM）加载数据时，不是按单个字节或单个元素读取的，而是以 Cache Line（缓存行，通常为 64 字节） 为单位加载的。

按行遍历时：当你访问元素 [i][j] 时，由于同一行的后续元素 [i][j+1] 在内存中是连续存放的，它们很可能已经被一起加载到了 CPU 的 L1/L2 缓存中。下一次访问直接命中缓存，速度极快。

按列遍历时：当你访问完 [i][j]，接下来要访问下一行的同一列 [i+1][j]。这两个元素在内存中相隔了一整行的大小（跨度为行宽）。这会导致当前的 Cache Line 失效（Cache Miss），CPU 不得不重新去主存或 L3 缓存中捞取数据，产生大量的等待延迟（Stall）。

2. Go 语言中二维切片的实现方式

在 Go 中，二维切片通常有两种常见形态，它们的列遍历性能受到的影响略有不同：

形态 A：切片套切片（[][]T，最常见）

内存布局：外层切片是一个包含多个内部切片 header 的数组，而每个内部切片指向各自独立的底层数组。

按列遍历的致命伤：不仅存在跨步访问的缓存未命中问题，还涉及指针解引用和不连续的内存块跳转，性能损耗最严重。

形态 B：扁平化一维切片模拟二维（[]T + 索引计算 i*cols + j）

内存布局：所有数据都在一个连续的底层大数组中。

按列遍历的表现：虽然内存是连续的，但由于访问跨度（Stride）等于列宽，每次跳跃都会跨越多个缓存行，依然会导致严重的缓存失效。

示例代码与基准测试直观感受

可以用以下思维来看这两种写法的差异：

Go
// 假设 matrix 是一个 N * N 的二维切片
// 【高性能：按行遍历】
for i := 0; i < N; i++ {
    for j := 0; j < N; j++ {
        val := matrix[i][j] // 内存连续，极度契合硬件预读机制
        _ = val
    }
}

// 【低性能：按列遍历】
for j := 0; j < N; j++ {
    for i := 0; i < N; i++ {
        val := matrix[i][j] // 内存跳跃，频繁触发 Cache Miss
        _ = val
    }
}
